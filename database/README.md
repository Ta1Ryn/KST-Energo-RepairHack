# PostgreSQL для команды BackendFork

Эта папка содержит схему и демонстрационный набор данных для PostgreSQL 16+.
Это SQL-файлы для создания базы, а не дамп работающего сервера.
В текущей среде PostgreSQL отсутствует и SQL ещё не выполнялся на живом сервере.

1. Создайте пустую базу fork в PostgreSQL.
2. Выполните schema.sql.
3. Выполните seed.sql только для тестовой базы.

Пример с установленным psql:

~~~powershell
createdb -h localhost -U postgres fork
psql -h localhost -U postgres -d fork -v ON_ERROR_STOP=1 -f schema.sql
psql -h localhost -U postgres -d fork -v ON_ERROR_STOP=1 -f seed.sql
~~~

В pgAdmin откройте Query Tool для базы fork и выполните файлы в том же порядке.
В DBeaver используйте выполнение SQL-скрипта целиком.

Схемы:
- catalog: оборудование, шильдики, паспорта, компоненты, установки;
- standards: нормативный ресурс, интервалы обслуживания, нормы датчиков;
- telemetry: датчики, история показаний, история наработки;
- knowledge: типы дефектов, инструкции, правила рекомендаций;
- reports: осмотры, выполненные работы, связи с фото;
- storage: метаданные фото и документов;
- ai: результаты анализа изображения;
- app: учётные записи и версия схемы.

seed.sql создаёт два образца оборудования, три компонента, четыре датчика,
тестовые нормы температуры, вибрации и давления, инструкции и правила рекомендаций.
QR: FORK:DEMO-001 и FORK:DEMO-002.
Все пределы и инструкции вымышленные и помечены как демонстрационные.
Учётная запись/PIN не включены; PIN настраивается через бэк на локальном ПК.
Отчёты и документы добавляются при работе приложения.

Колонки payload JSONB хранят дополнительные поля API и снимки отчётов.
Идентификаторы, связи, нормы и показания вынесены в отдельные таблицы.
Файлы PDF/изображений физически хранятся на сервере, в БД — их метаданные и ссылки.
Пересылайте этот архив коллегам; он не содержит PIN, паролей или ваших личных осмотров.
