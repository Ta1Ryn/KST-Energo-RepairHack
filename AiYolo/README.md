# YOLOv8: один демонстрационный насос

Выбран один пример оборудования: **Д160-112б**. Если в каталоге нет точной CAD-модели,
загрузчик может выбрать похожую модель серии Д и явно запишет это в `model-source.json`.
БГ11-23 больше не включён в текущий набор исходных материалов.

QR определяет насос. Один детектор YOLOv8 ищет на его фотографиях четыре типа дефектов:

| ID | Код для C# | Что размечаем |
|---|---|---|
| 0 | oilLeak | Видимые следы течи масла |
| 1 | displacement | Смещение узла или крепления относительно видимых ориентиров |
| 2 | corrosion | Видимую область коррозии |
| 3 | geometryDeformation | Изменение собственной формы детали |

Названия и порядок классов зафиксированы в `classes.json`. Обычные каталожные фотографии и
исправная 3D-модель не содержат автоматически размеченных дефектов.

## 1. Получить геометрию и исходные фотографии

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Get-PumpModel.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Fetch-References.ps1
```

Источники:
- https://www.hms-livgidromash.ru/documentation/3d/
- https://www.hms-livgidromash.ru/catalog/nasosy/d-1d-2d/d_160_112b_model_479.html

Загрузчик ищет прямые ссылки на CAD/архивы, предпочитая Д160-112б → Д160-112 → Д160 → другую модель серии Д.
Если страница требует браузер или содержит другую структуру ссылок, он сохранит доступную страницу
и сообщит об этом. Прямую ссылку из каталога можно передать через `-ModelUrl`.
Он не извлекает неизвестный архив и не изменяет CAD-файлы.

Когда файл появится, надо проверить формат, сборку и состав деталей. STEP/IGES обычно требуют
конвертации перед использованием в Blender. Генератор синтетических дефектов пока не реализован:
для его настройки нужна сама геометрия и понимание, где корпус, вал, муфта и крепления.

Для демонстрации на 3D можно позже подготовить варианты дефектов и рендеры с разными ракурсами,
светом, материалами, фоном и расположением повреждений. Разделять нужно целые сцены/варианты,
а не соседние кадры. Оценка на таких рендерах характеризует синтетический пример;
для камеры у настоящего насоса нужна отдельная проверка на реальных фотографиях.

## 2. Разметить фотографии

Открой `annotate.html` двойным щелчком. Выбери JPEG/PNG, назначь группу съёмки и источник,
обведи каждый видимый дефект, подтверди разметку. Для кадра без видимых дефектов есть отдельная кнопка.
Не назначай смещение, если по снимку невозможно установить нормальное положение детали.

Браузер обрабатывает изображения локально. Можно сохранить черновик JSON и восстановить его,
повторно выбрав те же фотографии. ZIP содержит нормализованные JPEG, YOLO TXT и `manifest.json`.
Поворот EXIF переносится в пиксели при экспорте, поэтому координаты рамок соответствуют изображению.

Начни с нескольких десятков разных примеров каждого дефекта для проверки процесса.
Для качества на новых снимках потребуется расширять набор по результатам ошибок модели;
количество само по себе не гарантирует точность. Добавляй похожие нормальные поверхности, блики,
грязь и следы краски, чтобы проверять ложные срабатывания.

В текущем сценарии один насос: разные независимые серии/сцены можно разделять между наборами,
но такая проверка не доказывает работу на других насосах. Нужны хотя бы три независимые группы,
и каждый из четырёх классов должен присутствовать в train, val и test.

Распакуй один экспорт в `annotations\batch01`, затем:

```powershell
node .\prepare-dataset.mjs .\annotations\batch01 .\datasets\pump-v1
```

Утилита проверяет классы, границы рамок, подтверждение пустой разметки, дубликаты файлов и группы.
Создаёт примерно 70/15/15 по группам; при малом числе групп пропорции будут отличаться.
Существующий датасет не перезаписывается. Проверка изображений через Pillow также выполняется перед обучением.

## 3. Подготовить GPU-окружение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup-Yolo.ps1
```

Устанавливаются Python 3.12.10 для текущего пользователя, отдельная `.venv`, PyTorch 2.7.1 CUDA 12.6,
Ultralytics и зависимости сервиса. Загрузка CUDA-пакетов может превышать 2 ГБ.
Версии сохраняются в `requirements.local.lock.txt`. Первичная подготовка требует интернета.
Исходные `yolov8n.pt` — веса общего распознавания объектов для дообучения; сервис дефектов их не примет.
После установки скрипт проверяет Python-файлы, контракт ответа и доступность GPU.

## 4. Обучить и оценить

```powershell
.\.venv\Scripts\python.exe .\train.py --data .\datasets\pump-v1\dataset.yaml --epochs 100 --batch 8 --imgsz 640
```

Это начальные параметры для RTX 4060 8 ГБ. При нехватке видеопамяти уменьши `--batch` до 4.
Переход на CPU не происходит молча; его можно выбрать явно через `--device cpu`.
Каждый запуск сохраняется отдельно в `runs`. Указатель `model.local.json` появляется только после
успешного обучения и проверки `best.pt`. До этого сервис не запускается с фиктивной моделью.

Во время разработки смотри precision/recall и ошибки каждого класса на val. После выбора модели
один раз оцени отложенный test, не подбирая по нему параметры:

```powershell
.\.venv\Scripts\python.exe .\evaluate.py --data .\datasets\pump-v1\dataset.yaml
```

## 5. Подключить к бэку

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Yolo.ps1
```

Сервис слушает `127.0.0.1:8001`, `GET /health`, `POST /analyze`.
В `POST /analyze` передаются multipart `file`, `equipmentId`, `componentId`, `installationId`.
Ответ соответствует `AiResult` и `Detection` существующего C# бэка.
Рамки переводятся из центра YOLO в **левый верхний угол + ширина/высота**, координаты 0–1.

В другом PowerShell из корня `fork`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -AiUrl 'http://127.0.0.1:8001'
```

Перед загрузкой с телефона надо нормализовать поворот JPEG в пиксели. Сервис отклоняет
неприменённый EXIF-поворот, чтобы рамки не смещались относительно исходного фото.
Порог детекции по умолчанию 0.35 — начальное значение, его нужно выбрать по проверочным данным.
Отсутствие рамок возвращает `checkRecommended`, а не заключение об исправности оборудования.
ИИ указывает предполагаемые дефекты; обслуживание и ресурс определяются нормами и правилами бэка.
